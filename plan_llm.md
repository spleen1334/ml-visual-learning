# Chapter 99 · Large Language Models (LLMs)

All fourteen lessons are implemented, checked and committed individually. Preserve this one-reviewable-lesson workflow for later changes; do not batch unfinished content into publication.

## Teaching direction

Start with a concrete question, a prominent plain definition, and one central visual. Keep explanations short and next to the thing they explain. Introduce one idea at a time, then reuse it. Use meaningful numbers and show where they come from. New mathematical symbols get names and a small worked example before a general equation. No prerequisites in calculus, linear algebra, or NLP are assumed.

The first lesson establishes the observable loop: context → probabilities → chosen token → updated context. Later lessons open the box progressively, without retroactively presenting the first lesson's authored probabilities as neural-network output.

Use the existing teal/cream theme, readable definitions, shared icon-only `PlaybackButton`, autoplay plus Previous/Next for steps, keyboard access, and reduced-motion completed views with manual exploration. Navigation stays ungated. Future outlines do not enter lesson pagination. Desktop browser review is required before reporting a lesson ready.

## Two distinct demonstrations

**Inspectable toy decoder (introduced gradually, fully connected in 99.14).** Use a small fixed vocabulary, one decoder block, hidden width 4, two attention heads of width 2 each, and a small feed-forward width such as 8. Keep contexts short enough to inspect every row. Show supplied deterministic embeddings and weights, intermediate arrays, dimensions, causal mask, and output values; do not claim that these weights were learned or that the toy has useful language ability. Choose and freeze the vocabulary/weights with the 99.3 implementation so subsequent lessons reuse exactly the same data. Use a decoder-only design, with no encoder or cross-attention. Explicitly distinguish this adaptation from the original encoder–decoder Transformer paper.

Keep the math in small pure functions and reveal one stage per lesson. Attention is a weighted mixture, not a human explanation of reasoning. Use scaled dot products, a stable softmax, masked future positions, head concatenation/output projection, residual additions, a documented normalization placement, and the position-wise feed-forward transformation. Fix and document normalization epsilon and activation. Avoid quietly mixing pre-norm and post-norm. Compute actual intermediate numbers rather than animating arbitrary labels. Validate matrix shapes, normalization, causal behavior, and numerical results with hand-checkable fixtures. No model API is needed.

**A separate, genuinely trained tiny classifier (99.10).** Start with a few visible labeled two-feature records, a small classifier and a deterministic initial state. Show a forward pass, predicted probability, loss, gradients, a weight update, and changed predictions/loss. Include a separate held-out prediction input. Show all parameters and reset behavior. This demonstrates actual parameter learning; label it as a classifier, not a trained LLM or a substitute for language-model training. Explain how the same loss/gradient/update pattern scales to next-token learning. Keep this separate from the supplied-weight decoder and from 99.1's probability lookup tree.

## Lesson sequence and acceptance checks

| Lesson | Question and central visual | Gentle mathematics and interaction | Specific verification |
| --- | --- | --- | --- |
| **99.1 What does an LLM predict?** | Prominent next-token definition; one probability bar chart beside the current text. Show read → choose → append → repeat, ending with a stop token. | Hand-chosen distributions totaling 100%. Select alternatives to change the next distribution. Play/Next choose the maximum; Previous returns to a prior context. Brief token and inference/parameters reminders. No forward engine yet. | Validate every tree distribution and branch, total path mass, stop behavior, generated text/spacing and rollback. Browser-test alternatives, autoplay completion, replay/reset, keyboard and reduced motion. |
| **99.2 Tokenization: text into token IDs** | Why a token need not be a word. Text → colored pieces → IDs, using an explicitly named vocabulary/tokenizer. | A tiny reversible lookup and visible spaces/punctuation; compare a whole word and a subword split. Define vocabulary and unknown/special tokens. Do not imply the toy matches all production tokenizers. | Round-trip supported strings, spaces, punctuation, special markers and unsupported-input behavior. Browser-check readable token boundaries and IDs. |
| **99.3 Embeddings and position** | IDs → rows of four numbers; then add a position vector to each row. | Define a vector as a short list of numbers, then show one elementwise addition. Freeze the toy vocabulary, supplied embedding table and position method. Explain that token IDs are labels rather than numeric meaning. | Verify lookup, dimensions, elementwise sums, repeated token at different positions, and exact displayed values. |
| **99.4 The neural network inside** | Trace a small input vector through learned-number multipliers, sums and an activation. | Explain weight, bias, dot product and nonlinear activation with a few visible multiplications. Define a parameter; supplied weights remain fixed in this lesson. Avoid claiming each coordinate has a fixed human meaning. | Hand-calculate one neuron and activation, check shape and parameter provenance, and connect changed input to changed output without claiming training. |
| **99.5 Attention: queries, keys, and values** | One selected token forms Q; compare it with K rows, then mix V rows with the resulting attention weights. | Define query/key/value as transformed number lists. Show one dot product, divide by √head-width, convert scores to weights, and one weighted sum. Softmax can be a clearly labeled conversion until 99.8 opens it. | Check Q/K/V projections, scale, weights summing to one and the weighted sum against a small fixture. No claim that attention weights prove reasoning or causation. |
| **99.6 Causal masking and multiple heads** | A position-by-position attention grid with future cells blocked; two heads side by side. | Apply the causal mask before softmax. Show why the current position may attend to itself, while future positions have zero weight. Each head uses width 2 within hidden width 4. | Verify zero future attention, each row's weight sum, no change to earlier outputs when later inputs change, and head concat/output dimensions. |
| **99.7 A Transformer block** | Connected block diagram: attention → residual/normalization → feed-forward → residual/normalization, following the chosen documented variant. | Explain residual as adding the incoming numbers back; normalization as rescaling a row; feed-forward as the same small network applied at each position. Show one row's actual numbers at each stage. | Verify residual arithmetic, normalization/epsilon, FFN shape and activation, chosen order, finite outputs and a full-block fixture. Show all connecting arrows. |
| **99.8 Logits and softmax** | Final hidden row → one score per vocabulary token → probability bars. | Define logit as an unnormalized score. Show exponentiation and dividing by the sum, first with three small scores; use max-subtraction for numerical stability and explain it briefly. | Verify sum-to-one, nonnegative probabilities, uniform equal scores, invariance to a shared shift, ordering, and finite results with large scores. |
| **99.9 Sampling and temperature** | Reuse a fixed logit vector and show the distribution flatten/sharpen; trace a random draw to its selected interval. | Show score divided by positive temperature and seeded categorical sampling. Contrast choosing the maximum with sampling; optional top-k/top-p only after the core is clear. Randomness changes selection, not model weights. | Check temperature domain, normalized distributions, reproducibility with a seed, cumulative boundaries, greedy behavior and a deterministic sampling-frequency sanity check if useful. |
| **99.10 Training: loss and gradients** | Visible data → actual tiny classifier fitting → changed parameters → separate prediction. Then connect that pattern to next-token targets. | Explain cross-entropy as a larger penalty for assigning a low probability to the observed target. Start with one target, then averaging. Gradient indicates how a small weight change affects loss; show one small update, not an unexplained calculus wall. | Check a hand-calculated loss/update, gradient by finite differences, deterministic reset/training, decreasing loss on the chosen stable step size, finite parameters and separate prediction behavior. Label in-sample improvement correctly. |
| **99.11 Pretraining, instructions, and preferences** | A connected sequence showing what data and objective enter each stage. | Pretraining predicts next tokens from text; supervised instruction tuning uses prompt/response examples; preference methods use comparisons or preference signals. Show one concrete example per stage without simulating a large run. Distinguish objectives, data and resulting behavior. | Verify labels and arrows against primary sources; distinguish preference optimization families, avoid implying one universal recipe, and avoid promises of truthfulness from preference fitting. |
| **99.12 Context, memory, retrieval, and tools** | Compare fixed parameters, current context, stored notes, retrieved passages, and external tool results in one connected request path. | A small request demonstrates what is put into context and what remains outside. Define context window, retrieval and tool use. A model requesting a tool is distinct from an application executing it. | Trace which inputs are visible at generation, retrieval failure and context limits; distinguish persistent storage from parameter updates and from runtime context. No actual external service required. |
| **99.13 Limitations and evaluation** | Inspect a few concrete outputs against task-specific checks: correctness, groundedness, uncertainty, robustness and held-out performance. | Show how an evaluation numerator/denominator is formed. Distinguish likely continuation from verified truth, and a small example score from general model ability. Include ambiguity and plausible-but-wrong output without overgeneralizing. | Check calculations and exact scoring rules; separate evaluation cases from training examples, flag coverage limits, and verify any factual claim about model capabilities with current primary evidence. |
| **99.14 The full LLM pipeline** | Reassemble the same inspectable decoder: text → IDs → embeddings/position → masked two-head block → final scores → probabilities → selected token → updated context. | Trace one token end to end with actual arrays, names and shapes, then repeat until a stop condition or short length cap. Keep full pipeline visible while highlighting the selected stage. Briefly locate training, stored parameters, retrieval and tools around inference. | End-to-end deterministic fixture, intermediate value consistency with prior lessons, masking, greedy/seeded sample paths, stop/length behavior, no hidden API, and browser test of the complete/manual/reduced-motion sequence. |

## Sources and limitations

The local Visual Guide does not provide a corresponding Chapter 99. Use primary references, save the exact worked values and document adaptations in `docs/CHAPTER_99_SOURCE_NOTES.md`. The sources verified for the first lesson are [Hugging Face causal language modeling](https://huggingface.co/docs/transformers/tasks/language_modeling), [Hugging Face tokenization](https://huggingface.co/docs/transformers/main/en/tokenizer_summary), and [Vaswani et al., Attention Is All You Need](https://arxiv.org/html/1706.03762v7). Later topics need their own targeted primary-source checks before implementation, particularly post-training, tool execution and evaluation.

99.1 is an authored lookup tree, the later decoder has supplied weights, and the classifier demonstration will actually fit parameters. Keep these boundaries visible. None of the tiny examples establishes real-world LLM quality or reproduces the scale of a production training run.
