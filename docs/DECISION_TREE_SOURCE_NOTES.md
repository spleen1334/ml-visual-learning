## Source values and math boundaries

The Trip Genie workbook dataset is distinct from the churn examples on PDF pp. 123–131; keep these examples separate. `Sessions_10=1` means the customer completed **more than ten sessions** (not an exact session count or continuous time-on-site measurement). The source story/assignment mentions time on site, but this workbook's actual IV is the binary sessions flag.

For any binary node, `H(p)=−p log₂p−(1−p)log₂(1−p)`, using H=0 at p=0 or 1. A split's information gain is the parent entropy minus the **branch-size-weighted average** child entropy. The PDF labels branch-wise parent-minus-child entropy drops (for the churn split, about .09 and .46) as gains; these are not the aggregate information gain of the whole split. The workbook's `S8`, `S39`, `AD8`, and `AD25` likewise subtract individual child entropies from their parent without weighting/combining siblings. This is a methodological error: faithfully display source branch counts/entropies, but calculate any aggregate information gain from both children and state its weighted denominator clearly.

Random forest course wording says randomization removes bias / “virtually guarantee[s] exploring all possible options.” Random sampling does not guarantee coverage of every candidate; describe it as varying the trees to reduce their dependence, with majority vote, if clarification is needed. For the case worksheet, a source-subtitle claim says that every customer with >10 sessions who follows Facebook subscribed and that non-followers unsubscribed. Cached workbook outputs contradict this: the matching branch is 12/15 subscribed and the other is 5/11 subscribed (6/11 did not). Preserve counts; do not repeat the claim as a certainty. Also, the saved `Decision Trees` second-split B panel has cached `#REF!` formulas at `AI35:AJ36` and dependent `AH40:AJ41`; it is an incomplete/invalid state. The pivot sheet displays all records, not those errors.

The churn example has another source inconsistency: p124–127 and subtitles start from 10 churn / 10 not, but the later-login children are 4Y/8N and 7Y/1N, which sum to 11Y/9N. The class totals therefore cannot all be true at once. With the child counts as shown, weighted child entropy is 0.7686. If the parent is reconciled to the child counts (11/20 churn, 9/20 not; H=0.9928), gain is 0.2242 bits. If the printed balanced parent is retained (H=1), gain is 0.2314 bits. Displayed child entropies round to .91 and .54; weighting those rounded values gives about .23, not either branch-only delta. Preserve the source counts and identify which parent assumption is used if reproducing these slides.

In subtitles, `12. Decision Tree Examples.vtt` says the final 1Y/3N leaf predicts a 52-year-old customer, after earlier explaining the age-35 right branch as 7Y/0N; PDF p128 likewise routes age 52 to that pure churn leaf. The subsequent 3-day/$28/90-day example traverses the left side to the 1Y/3N leaf and PDF p129 predicts no churn. Keep the shown tree paths/counts explicit if reproducing these slides; do not resolve this conflict by silently altering the source tree.
